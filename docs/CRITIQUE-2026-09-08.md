# BERT app critique — 2026-09-08

Review baseline: `f43a0ab`. Scope: shipped Android source, its data model and widgets. The user clarified that this is a general BERT app; widgets are one feature. The unshipped iOS scaffold is outside this implementation pass. The Farmhalla game rubric does not apply to this app.

## Judgment

The baseline has competent data validation but weak product structure. It is a widget setup screen that accumulated unrelated features. Adding another large panel would compound the problem. A general BERT app needs a recognizable home, clear feature destinations, and useful things to do without owning the token.

This pass establishes that structure. It does **not** establish a complete community platform: the home currently introduces native tools and opens ecosystem destinations in the browser. A directory alone will not create a strong repeat-use habit.

## Load-bearing findings

1. **P1 — The app can assert connectivity it does not have.** Baseline `MainActivity.kt:279` renders `MARKET ONLINE` whenever `refreshing` is false, independently of loading success. Baseline `data/BERTQuote.kt:16` trusts the persisted server freshness string forever. Repro: cache a fresh response, stop the network, reopen the app. The header can say online over unavailable/cached data. Fix: remove the unconditional claim, show quote age and refresh failure, and compute staleness against the current clock. Unit gate: `:app:testDebugUnitTest`, cases in `BERTCompanionTest`.
2. **P1 — The first screen serves the newest feature, not the app's purpose.** Baseline `MainActivity.kt:128` places the full Theme Studio ahead of every quote/loading/error state. Its preview alone is 300 dp tall (`:245`); headings and wallpaper actions come on top. No top-level navigation exists. Fix: a BERT home and persistent Home / Market / Holdings / Studio destinations, with widgets inside Studio.
3. **P1 — The app's apparent live data can stop updating during an ordinary session.** Baseline `MainActivity.kt:121` refreshes only in `LaunchedEffect(Unit)` and on manual request. A foreground screen does not react to background cache writes. Fix: refresh on entering STARTED and about every minute while started, update age separately, guard overlapping requests, and propagate coroutine cancellation. A widget render failure must not masquerade as a market-data failure.
4. **P2 — Browsing wallpapers changes another surface without an apply action.** Baseline `MainActivity.kt:164` saves and updates widgets inside `choose`; `:203` wires preview taps directly to that function. Fix: keep the preview distinct from the active palette; provide an explicit palette action and separate wallpaper actions.
5. **P2 — Holdings behave like a setup form rather than a feature.** Baseline `MainActivity.kt:361` always renders the editor, and access depends on obtaining a quote. Input strips all commas, silently turning `1,5` into `15`. Fix: an offline-accessible saved summary and editor, strict decimal/grouping validation, optional total cost, and an estimated unrealized gain/loss. Preserve the existing stored amount key so existing widgets continue working.
6. **P2 — Basic reading and navigation deserve more care.** Baseline uses 8–9 sp labels throughout and fixed page padding with target SDK 36. Android's system bars can obscure content at that target. Fix: native Scaffold safe-drawing insets, dark Material colors, larger labels, stacked market metrics, and preserved tab state. Actual large-text and device checks remain the standard; a build is not proof of visual quality. Reference: [Android window insets](https://developer.android.com/develop/ui/compose/system/insets).

## Next features, in order

1. **A real Play / Explore destination.** Curate the actual BERT experiences and games with useful descriptions and an explicit browser/native distinction. Validate each destination on mobile. Do not ship empty tiles or announce integrations that are just links.
2. **A small published BERT updates feed.** Give people a reason to return: dated releases, events and new art, each with a canonical source. This needs an actual content owner and publishing source before it deserves a home-screen feed.
3. **Saved favorites and recently used experiences.** Once the ecosystem has enough destinations to browse, let people shape their home. Avoid an account requirement until synchronization adds value.
4. **A better Studio.** Separate Home/Lock previews, widget previews and a measured apply flow on real launchers. The inherited combined wallpaper apply remains non-atomic: Home can succeed before Lock fails.
5. **Optional price alerts.** Secondary to the general BERT experience. Implement with explicit thresholds, notification permission, deduplication, and honest delivery limitations; do not imply precise real-time alerts from periodic Android work.
